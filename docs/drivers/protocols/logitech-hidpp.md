# 罗技 HID++ 2.0（MacPulse 实现）

消息格式、功能号和参数位置参考 [OpenLogi](https://github.com/AprilNEA/OpenLogi)（MIT / Apache-2.0）。实现在 `Source/Logitech.swift`。**没有实机测试过。**

## 接口

- VID `0x046D`。
- 接收器和有线设备：Usage Page `0xFF00`，Usage `0x0002`。蓝牙直连：Usage Page `0xFF43`，Usage `0x0202`。
- PID 在 `0xC5xx` 段的是接收器（Unifying、Bolt、Nano、Lightspeed），设备号试 1–6；直连设备的设备号是 `0xFF`。
- 部分接收器要先在“系统设置 → 隐私与安全性 → 输入监控”里允许，才能打开这个通道。Windows 上不需要这一步。

## 消息

长报告，Report ID `0x11`，共 20 字节：

| 下标 | 值 |
|---|---|
| 0 | `0x11` |
| 1 | 设备号 |
| 2 | 功能在这台设备上的下标（feature index） |
| 3 | `function << 4 \| 软件 ID`，MacPulse 用软件 ID `0x0A` |
| 4–19 | 参数 |

回复的第 0 字节是 `0x10` 或 `0x11`，下标 1–3 和请求一致，参数从第 4 字节开始。出错时：

- `[1]=设备号, [2]=0xFF, [3]=功能下标, [4]=请求的第 3 字节, [5]=错误码`：HID++ 2.0 错误
- `[2]=0x8F`：HID++ 1.0 错误，通常是接收器这个槽位没有设备，或设备在睡眠

## 找功能

功能下标因设备而异。先用 Root（下标 0）的 function 0 查：参数是功能 ID 的两个字节，回复 `[0]` 是下标，0 表示没有这个功能。MacPulse 查这些功能：

| 功能 ID | 名称 | 用到的 function |
|---|---|---|
| `0x0005` | 设备名 | 0 取长度，1 按偏移取名字（每次 16 字节，UTF-8） |
| `0x1004` | Unified Battery | 1 状态：`[0]` 电量，`[2]` 1–4 为充电中 |
| `0x1000` | Battery Status | 0 状态：`[0]` 电量，`[2]` 1–3 为充电中（老设备） |
| `0x2201` | Adjustable DPI | 1 列表（参数 `[0]`），2 读当前（`[1..2]`），3 设置（`[0, hi, lo]`） |
| `0x2111` | SmartShift（带力度） | 1 读 `[模式, 阈值, 力度]`，2 写 |
| `0x2110` | SmartShift | 0 读 `[模式, 阈值]`，1 写 |
| `0x2121` | Hi-res 滚轮 | 1 读模式标志，2 写；bit 2 = 反向 |

SmartShift 模式 1 = 自由滚动，2 = 段落；阈值 255 = 一直段落（关掉 SmartShift）。写 0 表示这个字段不变。

DPI 列表是大端 2 字节值，以 0 结束；最高 3 位是 `111` 的值表示步进：`低 13 位` 是步长，后面紧跟的值是终点，从上一个值按步长一直到终点。

改滚轮方向时只改 bit 2，目标和分辨率两个标志保持原样。每次写完都读回来核对。
